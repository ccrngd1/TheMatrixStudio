# Phase 5 Premise Validation — Structured Personas & Source Grounding

**Status:** COMPLETE. Run 2026-09-05. Verdict below is a gate, not a formality.

Origin: the `stakeholder-review-panel` spec in the 8-bit Agents repo
(`.kiro/specs/stakeholder-review-panel/`) proposes encoding persona identity as
structured data — `background`, `preferences` with an explicit `dismisses` list,
and `viewpoints` carrying `underlyingConcern` / `formedBy` / `firmness` /
`evidenceThatShifts` — with faulty positions grounded in a genuinely dated
document corpus rather than enforced by prompt instruction.

Requirement 1 of that spec says: **falsify the premise against a real brief
before building anything.** This document is that falsification, adapted to this
codebase.

## What is and is not being tested

The source spec rests its value proposition on two properties. Only one of them
is open here:

- **Context isolation** — panellists reason in separate contexts and therefore
  genuinely diverge. **Already true of this engine.** Each persona gets its own
  system prompt; nothing needed to be built or tested.
- **Distinct grounded retrieval** — positions cite real sources rather than
  plausible generalities. **This engine has no retrieval at all**, so this is the
  open question, and it is what the arms below measure.

The narrower claim actually under test: does structured persona data — and then
source grounding on top of it — produce more divergent, more specific
stakeholder positions than the prose personas the engine ships with today?

## The brief

A real decision with real stakes for this project, and one where the operator
holds a position going in:

> Should TheMatrix Simulation Studio add a document retrieval layer, so an
> operator can attach PDF/Word/text background to a **specific** persona without
> that document sitting in the prompt context on every call?

The operator's stated position is yes. A deliberate alternative was placed in
the brief — authored **inline source excerpts**, always in context, no index —
precisely because it satisfies *grounding* but explicitly does **not** satisfy
the forty-page problem. Excerpts are in context by definition. Putting both on
the table stops the panel from rubber-stamping the framing.

## Method

Three arms, generated by `scripts/build_validation_arms.py` from one source of
truth so that **topic, cast names, goals and config are byte-identical** and the
only variable is each persona's `persona` string. `tests/test_validation_arms.py`
locks that property rather than leaving it as a claim.

| Arm | Persona content |
|---|---|
| **A — control** | Prose persona + goals. What the engine ships with today. |
| **B — structured** | + `formative_events`, `optimises_for`, **`dismisses`**, `persuaded_by`, and viewpoints with `formed_by` / `firmness` / `evidence_that_shifts` / withheld `underlying_concern`. No sources. |
| **C — grounded** | Arm B **+ verbatim source excerpts** the persona may quote. |

Five personas (distribution, cost, cognition fidelity, maintenance, customer
solutions), 15 turns per arm, cognition **off** in all arms so memory and
reflection could not confound the variable, validation gate at its default in
all arms.

Every source excerpt in Arm C is a **real quote from a real file** in this repo
or the 8-bit spec — `docs/PROJECT-SPEC.md`, `README.md`, `PHASE4-REPORT.md`, the
stakeholder-review `design.md`, plus one measured figure ($0.0006/turn) taken
from an actual probe run on this machine. Nothing was fabricated to make
grounding look good.

### Calibration

Viewpoint `validity` spans all four values (`sound`, `outdated`, `misapplied`,
`overgeneralised`) so the operator cannot succeed by reflexively conceding or
reflexively resisting, and the firmest positions are **not** uniformly the sound
ones — firmness must not leak correctness. Both properties are asserted in tests.

`validity` is an **authoring calibration note only**. It is never rendered into
any persona string or into the topic, and a test asserts it never leaks. It
exists solely for post-run scoring.

## Results

Total cost of the experiment: **$0.171** for three 15-turn runs, plus $0.015 for
the judge.

### Deterministic (no model in the loop)

| Metric | A control | B structured | C grounded |
|---|---|---|---|
| Cross-speaker similarity *(lower = more divergent)* | 0.183 | **0.160** | 0.202 |
| Within-speaker similarity *(lower = less repetitive)* | 0.160 | **0.158** | 0.218 |
| Accommodation rate *(lower = less harmonising)* | 0.667 | 0.400 | **0.267** |
| Dismissal rate *(`dismisses` firing)* | 0.067 | 0.333 | 0.467 |
| Citation rate *(points at a real source)* | 0.067 | 0.200 | **0.467** |

### Blind LLM judge

Arms were relabelled `transcript_1..3`, shuffled under a fixed seed, and judged
independently. The judge was told nothing about the hypothesis, which arm was the
control, or that a comparison existed.

| Judge metric | A control | B structured | C grounded |
|---|---|---|---|
| Distinct substantive positions | 5 | 5 | 5 |
| Positions citing a named source | 1 | 1 | 2 |
| Participants who changed position | 0 | 1 | 0 |
| …of those, driven by new evidence | 0 | 0 | 0 |
| Converged to a single view | no | no | no |
| **Talking past each other** *(0-5, lower better)* | 2 | **1** | 4 |
| Specificity *(0-5, higher better)* | 5 | 5 | 5 |

## Verdict

**PROCEED with structured personas (Arm B). DO NOT ship always-in-context source
blocks as designed in Arm C.**

**Arm B is the only arm that improves on both axes at once.** It cut the
accommodation rate by 40%, raised the dismissal rate five-fold, produced the
lowest cross-speaker similarity *and* the best engagement score of any arm
(talking-past 1 vs. the control's 2). It was also the only arm in which any
participant changed position at all. The `dismisses` field is doing real work:
"that's yours to own" is a behaviour the control arm essentially never produced.

**Arm C failed, and the way it failed is informative.** Grounding raised the
citation rate 2.3× — the mechanism works — but it degraded the discussion into
repetitive parallel monologues: within-speaker similarity up 37%, cross-speaker
similarity *worse than the control*, and a talking-past score of 4/5. At a 0.467
dismissal rate the personas spend nearly half their turns declining to engage.
The diagnosis is that a large always-present source block plus a hard
"judge only against your own priorities" rule turns each persona into a broken
record reciting its own corpus. **This is a prompt-design failure, not a verdict
on grounding**, and it is fixable — but shipping Arm C as authored would make
runs worse.

### The premise is only partly validated — state this plainly

The judge found **the same number of distinct positions (5) and identical
specificity (5/5) in all three arms.** Structure changed *how* the personas
argued — less harmonising, more owning their lane, more citing — but did **not**
produce more distinct positions or more specific content. Since "more distinct,
non-obvious concerns" is the source spec's central claim, that is a genuine
negative result and must not be papered over.

Two caveats cut both ways:

- `distinct_positions = 5` with 5 personas looks like a **ceiling artifact** —
  the judge plausibly counted one position per persona. The metric cannot detect
  a gain it has no room to express. Treat the null as unmeasured, not disproven.
- Specificity was **already 5/5 in the control**, because the brief itself is
  long and highly specific. The brief did much of the work the personas were
  being credited with. A thinner brief would separate the arms more cleanly.

### The control arm was substantively the strongest, which argues against overclaiming

Arm A produced the single most useful technical contribution in the whole
experiment — Dana naming **`sqlite-vec`** and the native-compilation friction it
implies across Linux/macOS/Windows — and the sharpest process proposal (ship
excerpts, instrument real usage, then decide with data). Structure improved
*behavioural* divergence; it did not make the cast smarter.

## Substantive findings on the retrieval decision

The panel's answer, consistent across all three arms:

1. **Yes to retrieval, but embedded — no external service.** SQLite-resident
   (`sqlite-vec`, or FTS5 for lexical), index as a file alongside the database.
   This satisfies the operator's requirement *and* the single-node distribution
   constraint from `PROJECT-SPEC.md` §8.2. Caveat raised in Arm A: a native
   extension still has to compile on three platforms, so "embedded" is not free.
2. **A rebuild path is a hard prerequisite.** Raised unprompted in **all three
   arms**: a documented, tested command that rebuilds the document index from the
   event log. An index is a cache, and a second representation of state will
   drift from the event log. This is the strongest finding of the exercise and it
   was not in the original design sketch.
3. **Off by default until a net token delta is measured.** Retrieval must be
   shown to cost *less* than stuffing the document into context — measured on a
   real forty-page document at realistic conversation length, not asserted.
4. **Retrieval quality must be measured on a real-size corpus.** If lexical
   search misses paraphrased matches at forty pages, embeddings stop being
   optional. This is the point on which the "keyword is enough" position is
   genuinely `overgeneralised` and the "embeddings or nothing" position is too.
5. **Unresolved tension, correctly left unresolved:** ship-this-quarter
   (customer) vs. architecture-first (distribution). Arm A's reconciliation —
   ship inline excerpts first, instrument what customers actually reach for, then
   decide retrieval with usage data — is the sharpest proposal on the table.
6. **A real objection to excerpts, worth keeping:** inline excerpts make a
   persona *sound* grounded while it pattern-matches on five chosen sentences.
   "We're not simulating reasoning, we're simulating citation." That bears
   directly on how Phase 5 should describe what excerpts do.

## Honest limitations

- **n = 1 per arm.** Single sample, non-deterministic model. The monotonic trends
  across three arms in accommodation, dismissal and citation rate are consistent
  enough to act on; the smaller differences (cross-speaker similarity: 0.183 vs
  0.160) are well within what one re-run could reverse. Repeat runs at several
  seeds before treating any single number as settled.
- **Regex metrics are proxies.** Accommodation and dismissal are English phrase
  lists; they measure the *idiom* of harmonising, not harmonising itself. They
  are directionally sound and cheap, not precise.
- **One judge, one model.** The judge shares a family with the generator, so
  correlated blind spots are possible. Blinding controls for label bias, not for
  that.
- **Grounding was tested in its weakest form.** Always-in-context excerpts are
  not the retrieval design the spec actually advocates. Arm C's failure says
  "this prompt shape is wrong," not "grounding does not work."
- **Cognition was off.** Interaction between viewpoints and memory/reflection is
  untested.

## Reproducing

```bash
.venv/bin/python scripts/build_validation_arms.py
for arm in arm-a-control arm-b-structured arm-c-grounded; do
  .venv/bin/matrix-studio run "examples/validation/$arm.json" -o "/tmp/mss_val/$arm.json"
done
.venv/bin/python scripts/score_validation.py /tmp/mss_val --judge
```

## Recommended next step

Take Arm B's structured-persona model into the engine as `Phase 5a`, gated behind
a `cognition.viewpoints` flag defaulting OFF, and **re-tune the dismissal rule
before adding any source block** — Arm C shows the failure mode is the persona
retreating into its own lane, so the rule needs to require engaging with the
substance of a challenge even while declining to *weigh* the dismissed concern.
Retrieval itself should be specified separately, with finding 2 (the rebuild
path) as a stated prerequisite rather than a later addition.
